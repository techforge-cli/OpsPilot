Safety

The analyzer decides what should happen. The safety guard decides whether it may. It runs before every remediation and every verifier and returns a SafetyResult with allowed, requires_confirmation, and the list of reasons.

What blocks a run

CheckLimit
Empty playbookA playbook with no steps is blocked.
Host allowlistIf applies_to.hosts.tags is set, the host must share a tag.
Command length2000 characters maximum per step.
Step timeoutMust be greater than 0 and at most 300 seconds.
DenylistAny matching pattern blocks the whole playbook.
Verifier read-onlyVerifier steps must not contain write markers.

Denylist patterns

The guard refuses command shapes that write to the wrong place or open a shell back to somewhere else. The published set covers:

  • Fork bombs and reverse shells.
  • Recursive deletes of / or /*.
  • Disk formatting and raw device writes: mkfs, dd if=.
  • Piping a download straight into a shell.
  • Writes to /etc/shadow, /etc/sudoers, /boot, /proc/sys, and other system paths.
  • Raw socket and node helpers: /dev/tcp/, nc -e, ncat, mknod, mkfifo, bash -i.
Approve is not a bypass. Confirming a playbook approves it for this run; it does not let a denylisted command through. The denylist is evaluated the same way whether a run is automatic or confirmed.

When confirmation is required

A run needs a human click if any of these is true:

  • The playbook's risk is not auto.
  • The playbook source is not builtin (custom playbooks always confirm).
  • Global auto mode is off (OPSPILOT_GLOBAL_AUTO_MODE=false, the default).
  • The playbook sets auto_run: false.

In other words, an automatic run requires all four: an auto risk tier, a builtin source, global auto mode on, and auto_run: true.

Verifier rules

A verifier is a playbook marked verifier: true. Its steps are checked against a read-only filter: any step containing >, >>, tee, rm, mv, cp, chmod, chown, dd, mkfs, or a systemctl stop/restart/disable is rejected. A verifier that writes is not a verifier.

Incident outcomes

  • resolved — the verifier exited 0 and the metric recheck passed.
  • unresolved_recommended — still broken after the attempt; OpsPilot makes one final recommendation-only follow-up and stops.
  • pending_confirmation — waiting on an admin click.
  • blocked — the guard refused the run.

No playbook match means no execution at all; the incident is logged with the model's explanation instead. Every one of these transitions is written to the audit journal.

Audit

Each safety decision records a safety_decision event with the playbook id, the allowed flag, and the reasons. Remediation runs record their commands, exit codes, stdout, and stderr. The journal is append-only JSONL under the data directory.
