Architecture

OpsPilot is deliberately one process. Every component shares one SQLite database and one audit journal, and they talk to each other in process rather than over a network. There is no broker, no worker fleet, and no external database.

One pass through the system

scheduler ──▶ collector ──▶ analyzer ──▶ safety ──▶ executor ──▶ incidents
   (30s)        (native)      (Ollama)     (guard)    (commands)    (lifecycle)
                    │                          │
                    └──────────▶ SQLite ◀──────┘
                                   │
                              audit.jsonl (append-only)
                                   │
                                web (FastAPI + HTMX)

Components

ModuleResponsibility
schedulerDrives the collection loop on the configured interval (30 seconds by default).
hostsInventory of local and SSH-reachable targets and their tags.
metricsNative metric collection from Linux tools and /proc.
collectorRuns collectors and builds the canonical snapshot JSON.
analyzerOllama client over the OpenAI-compatible API plus strict-response validation.
playbooksYAML catalog, builtin versus custom, immutable revisions.
safetyPolicy validator for commands, timeouts, risk, and host scope.
executorRuns playbook steps and verifier steps, capturing output.
incidentsIncident lifecycle and the final recommendation-only follow-up.
db / journal / auditSQLite tables, the audit writer, and the append-only JSONL journal.
webFastAPI, Jinja2 templates, and HTMX fragments for the dashboard.
configEnvironment-backed settings.

The LLM contract

The analyzer sends a compact snapshot to Ollama and parses a strict JSON response. The response names the issue, its severity, and the playbook and verifier to use. If the model returns something that does not fit the contract, no remediation is attempted.

{
  "issue_id": "docker_service_unhealthy",
  "severity": "high",
  "summary": "Docker daemon is not responding",
  "explanation": "docker info returned non-zero",
  "playbook_id": "restart-docker-unhealthy",
  "verifier_id": "docker-service-healthy"
}

Storage

  • SQLite holds hosts, snapshots, incidents, incident runs, playbook revisions, and settings.
  • audit.jsonl is append-only: one JSON object per line, written as things happen.
  • Private SSH key material is never stored in the database; only the key path is.

Execution targets

A host is local or ssh. SSH hosts use the configured private key path and the system ssh executable. OpsPilot does not generate keys and does not copy them for you. Every playbook run records the host_id it ran against.

Design trade-offs

  • SQLite over PostgreSQL — one less service to run; WAL is enough for a single admin box in this phase.
  • Strict JSON over free text — the model's answer must be machine-checkable before anything can run.
  • In-process over queues — the failure modes are local and visible, not distributed and mysterious.
