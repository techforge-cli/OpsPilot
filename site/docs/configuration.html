Configuration

All settings are environment variables prefixed with OPSPILOT_. They are read once at startup by the settings object in opspilot/config.py.

Environment variables

VariableDefaultPurpose
OPSPILOT_ADMIN_PASSWORDemptyEnables admin web mode. Empty means read-only.
OPSPILOT_BIND_HOST127.0.0.1Address the web server binds to.
OPSPILOT_BIND_PORT8443Port the web server binds to.
OPSPILOT_DATA_DIR/var/lib/opspilotDirectory for the SQLite database and audit journal.
OPSPILOT_OLLAMA_BASE_URLhttp://127.0.0.1:11434Ollama endpoint.
OPSPILOT_OLLAMA_MODELqwen2.5:7bModel used for analysis.
OPSPILOT_INTERVAL_SECONDS30Seconds between metric snapshots.
OPSPILOT_GLOBAL_AUTO_MODEfalseWhen true, playbooks with the auto risk tier may run without confirmation.
OPSPILOT_SSH_KEY_PATH/etc/opspilot/operator.keySSH key used to reach managed hosts.
OPSPILOT_LOG_LEVELINFOLog verbosity passed to the server.

Command-line overrides

The launcher accepts a couple of flags that override the environment for a single run.

opspilot --config-check        # validate settings and exit
opspilot --host 0.0.0.0        # override OPSPILOT_BIND_HOST
opspilot --port 9443           # override OPSPILOT_BIND_PORT

Read-only versus admin mode

The admin_password setting decides the mode. This is a deliberate default, not a hidden switch:

  • Empty password — read-only web mode. The dashboard renders state but rejects admin actions.
  • Password set — admin mode. Sign-in at /login unlocks actions such as confirmations and playbook management.
Bind carefully. The default bind is 127.0.0.1. Exposing the dashboard on a public interface puts both state and admin actions on the network, so pair a wider bind with a reverse proxy and TLS.

Data on disk

Everything durable lives under OPSPILOT_DATA_DIR:

  • opspilot.sqlite — hosts, snapshots, incidents, playbook revisions, settings.
  • audit.jsonl — append-only audit journal, one JSON object per line.

Back up the directory and you have backed up OpsPilot.
