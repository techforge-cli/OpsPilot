HTTP endpoints

OpsPilot serves an HTML dashboard rather than a JSON API. Pages are rendered with Jinja2 and updated with HTMX fragments. The only machine endpoint is the health check.

Health

MethodPathDescription
GET/healthzLiveness check. Returns a success response when the process is up.
 
curl -fsS http://127.0.0.1:8443/healthz

Authentication

MethodPathDescription
GET/loginSign-in page.
POST/loginAccepts a form or JSON body with username and password; sets the session cookie.
POST/logoutClears the session cookie.
Read-only mode. With no OPSPILOT_ADMIN_PASSWORD, the dashboard serves read-only pages and the confirm and dismiss endpoints return 403.

Dashboard

MethodPathDescription
GET/Status overview.
GET/hostsHost inventory and their state.
GET/incidentsIncident list and lifecycle status.
GET/incidents/{id}One incident with its recommendation, verifier output, and run history.
POST/incidents/{id}/confirmRuns the incident's playbook. Single-flight: an incident not in pending_confirmation is refused with 409.
POST/incidents/{id}/dismissCloses an active incident without running anything.
GET/partials/statusHTMX fragment with per-host live status.
GET/playbooksPlaybook catalog.
GET/auditAudit journal view.
GET/settingsEffective settings.

All dashboard routes return HTML. HTMX requests receive the matching fragment so the page can update in place without a full reload.

Health check example

# is it up?
curl -fsS http://127.0.0.1:8443/healthz

# follow the audit journal while you work
tail -f /var/lib/opspilot/audit/audit.jsonl | jq .

Storage artifacts

There is no API to import or export; the durable record is on disk in the data directory. Read the SQLite database directly or stream the JSONL journal.

  • opspilot.sqlite — structured state.
  • audit.jsonl — every event, append-only.
