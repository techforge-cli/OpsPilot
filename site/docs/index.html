Getting started

OpsPilot is a single FastAPI process for Debian-family servers. It collects native Linux metrics, analyzes them with a local Ollama model, and runs governed remediation playbooks. These steps take you from a clean checkout to a running dashboard.

Requirements

  • Python 3.11 or newer.
  • A Debian-family host (or a host you reach over SSH).
  • A reachable Ollama endpoint with a pulled model, for example qwen2.5:7b.

Install

python -m venv .venv
. .venv/bin/activate
pip install -e .

Configure

OpsPilot reads OPSPILOT_-prefixed environment variables. The two you almost always set first are the data directory and the admin password.

export OPSPILOT_DATA_DIR=/var/lib/opspilot
export OPSPILOT_ADMIN_PASSWORD='change-me'
Read-only mode. If OPSPILOT_ADMIN_PASSWORD is empty, the web dashboard runs in read-only mode and no admin actions are accepted.

Validate and run

opspilot --config-check
opspilot

--config-check validates settings, creates the data directory, and exits. Running opspilot starts the scheduler and the web server. Open http://127.0.0.1:8443/ by default and sign in with the admin password.

Run as a service

A systemd unit ships in the repository at systemd/opspilot.service. Install it, set the environment variables for the unit, then enable and start it.

sudo cp systemd/opspilot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now opspilot
